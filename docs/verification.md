# Game verification

Run `sh scripts/check.sh` with the pinned Godot 4.7.2 runtime. All suites use the current two-week policy campaign.

- Policy content checks cover all 150 packets, fourteen rules, the two-day blocks of additions, amendments, and retirements, keyword token boundaries, source line limits, per-file ink exceptions and tickets, credential, print, and disclosure boundaries, and whole-PR evidence for the diff budget, file cap, and travelling tests.
- Simulation and clock checks cover five-minute shifts, twenty-second arrivals, explicit selection, exact citations, consultation unlocks, immutable transitions, payroll, evenings, completion on the second Friday, and invalid action histories.
- Save checks exercise three independent slots, JSON round trips, backup recovery, malformed data, current tutorial progress, and rejection of unsupported formats. There is no compatibility campaign.
- Interface and application checks cover source rendering, compact rule descriptions, the absence of any Slouch icon, window, badge, or ticker card, the REVIEW icon and review notification card, notification counts, pause/focus handling, window layout, tutorial arrows (orientation goes straight to REVIEW), the cold-open → orientation → morning memo → shift sequence, and Morgan's end-of-day panel: it opens at every closing (and on an evening load) with her portrait, notes, and closing words, each described evening choice advances the day, and day 10 ends with RETURN TO MAIN MENU.
- Chat content checks (`test_chat`, `test_manager`, the DM checks in `test_encounters` and `test_trees`) keep the archived Slouch conversations and Morgan's `Chat.evening` report authored and audit-free.
- Press checks cover all five daily editions, clickable stories, memo gating, and newly introduced rules without leaking audit answers.
- Desktop-window checks cover dragging, resizing, maximize/restore, clipping, and supported viewport sizes.
- Music checks (`test_music`) load every stem and require a forward loop of exactly 16 bars at 125 BPM, continuation samples past the loop end, mono QOA, and identical lengths; check the state-to-layer mapping (intro only in the morning, menu, and end of day; the pulse early; hats and the opening figure mid-shift; the late layer from 16:00; layers that only thicken over the day; warm and bleak endings); check that changes wait for a bar line and fade over two bars, that pause and focus loss duck behind the bus low-pass, that the MUSIC toggle and volume persist, and that SYSTEM's controls drive the manager. Under `--headless` the stems stay silent unless a test sets `Music.play_headless`, as `test_music` does to check that they start in one mix step. `tools/music/compose.py` prints each stem's peak, RMS, K-weighted loudness, and loop-seam jump when it renders.

Native and single-thread Web exports use the Compatibility renderer. Screenshots under ignored `build/` provide visual checks of the actual native controls. `sh scripts/run.sh --script res://tools/capture.gd -- <dir>` renders the menu, cold open, orientation (the arrow on REVIEW, then the file dropdown), morning reader, the desktop mid-shift, Review, standards, a stamped review, Morgan's end-of-day panel (day 1, a later day, and the final RETURN TO MAIN MENU), an author pushing back (INSIST/WITHDRAW), an author revising at the desk (typing, then v2), and pause to PNGs. `sh scripts/run.sh --headless --script res://tools/encounter_flowchart.gd -- <out.html>` exports the encounter flow charts to a self-contained HTML page. Displayed source is never executed. Windows packaging, notarized distribution, sound effects, and comprehensive screen-reader support remain outside this milestone.
